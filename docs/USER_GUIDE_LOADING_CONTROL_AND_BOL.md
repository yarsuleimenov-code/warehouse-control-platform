# Инструкция по использованию Loading Control и Interstate BOL

Версия инструкции: 12 августа 2026 г.

## 1. Назначение системы

Warehouse Control Platform используется для:

- фиксации загрузки заказов на складе NY или CA;
- создания рейса и `TripID`;
- автоматического формирования Interstate BOL;
- приёмки и сверки груза на складе назначения;
- регистрации отсутствующих мест в `Missing`.

Interstate BOL работает как отдельный сервис. После создания рейса Warehouse Control передаёт его `TripID` в очередь BOL. Пользователю не нужно дополнительно нажимать кнопку генерации BOL.

## 2. Основной процесс

```text
Login
  → выбор Loading workflow и Truck
  → отметка загруженных заказов/мест
  → Save
  → Generate Trip
  → TripID записан в TripReports
  → BOL автоматически поставлен в очередь
  → PDF сохранён в Interstate BOL
  → PDF URL записан в BOL_Registry
  → склад назначения выполняет Unloading и Close Trip
```

Обычное время появления BOL — после ближайшего минутного запуска worker. При временной ошибке система выполняет повторные попытки. Часовая сверка ищет рейсы, уведомление о которых не дошло до очереди.

## 3. Вход в Warehouse Control

1. Откройте Web App Warehouse Control:
   [Warehouse Control Platform](https://script.google.com/a/macros/zaberman.com/s/AKfycbwCqLRwLHwmHrF9Sokc6vcQ2u6CXRHkNMckuawOwn2EdA_91snxJbMhF-hiirAl3dI/exec).
2. Введите `Username` и `Password`.
3. Нажмите **Login**.
4. Выберите доступный процесс:
   - **NY Loading** — отправка NY → CA;
   - **CA Loading** — отправка CA → NY;
   - **NY Unloading** — приёмка CA → NY;
   - **CA Unloading** — приёмка NY → CA.
5. Выберите фактически используемый **Truck**.
6. Откройте workflow.

Система запоминает выбранный контекст в браузере примерно на 12 часов. Кнопка **Change** возвращает к выбору workflow, **Logout** завершает локальную сессию.

## 4. Loading — фиксация загрузки

### 4.1 Поиск заказа

В верхней части экрана можно:

- найти заказ по `OrderID` или `Title`;
- отфильтровать заказы по цвету;
- отфильтровать по статусу.

Основные статусы:

| Статус | Значение |
|---|---|
| `Req.Pcs` | Количество мест не задано |
| `Not started` | Места заданы, но загрузка не отмечена |
| `Started` | Загружена часть либо общее количество неизвестно |
| `Completed` | Все заданные места отмечены загруженными |
| `Pending save` | Изменение сохранено только на устройстве и ещё не отправлено на сервер |
| `In trip` | Заказ уже отражён в сформированном рейсе |
| `Remaining` | После предыдущего рейса остался незагруженный остаток |

### 4.2 Если известно количество мест

1. В колонке Pieces задайте количество мест кнопками `−`/`+` или введите число вручную.
2. Нажмите **Open**.
3. Отметьте фактически загруженные кнопки `Piece 1`, `Piece 2` и т. д.
4. Загруженное место отображается зелёным.
5. Нажмите **Save**.
6. Дождитесь сообщения **Saved**.

Не отмечайте место, пока оно физически не загружено в truck.

### 4.3 Если количество мест неизвестно

Используйте `−`/`+` в колонке прогресса `Loaded / N`.

Текущее бизнес-правило:

- `LoadedPieces = 1` означает, что заказ зафиксирован как полностью загруженный;
- BOL показывает такой заказ как `1 pcs`;
- в BOL используется полный `Weight` заказа.

Не увеличивайте значение больше фактически загруженного количества заказов/единиц учёта.

### 4.4 Сохранение изменений

Нажмите **Save**, когда закончена текущая серия отметок.

- `Saved` — сервер подтвердил запись.
- `Unsaved changes` или `Pending save` — изменения ещё находятся на устройстве.
- `Save failed... Retry when connection is back` — изменения сохранены локально; восстановите соединение и нажмите **Retry Save**.

Не очищайте данные браузера и не выходите из workflow, пока есть несохранённые изменения.

## 5. Создание рейса

Перед созданием рейса проверьте:

- выбран правильный Loading workflow;
- выбран правильный truck;
- все фактически загруженные заказы/места отмечены;
- ошибочно отмеченные места сняты;
- вес и название заказа заполнены в исходном Orders sheet.

Далее:

1. Нажмите **Generate Trip**.
2. Система сначала автоматически отправит pending changes через Save.
3. Дождитесь блока **Trip created**.
4. Зафиксируйте показанный `TripID`, route, truck и количество orders.

Рейс создан только после появления сообщения `Trip generated: <TripID>` и блока подтверждения.

### Если Generate Trip завершился timeout

Не нажимайте кнопку многократно подряд.

1. Нажмите **Refresh**.
2. Проверьте, получили ли отмеченные заказы статус `In trip`.
3. При наличии доступа проверьте новый `TripID` в `TripReports`.
4. Повторяйте Generate Trip только если рейс действительно не был создан и остаются новые loaded items.

Причина: timeout браузера не гарантирует, что сервер не успел записать рейс.

## 6. Автоматическое формирование BOL

После успешного `Generate Trip` Warehouse Control автоматически вызывает BOL-сервис.

В BOL включаются:

- строки выбранного `TripID` со статусом `Started` или `Completed`;
- только строки с `LoadedPieces > 0`;
- полный `Weight` каждого уникального заказа;
- количество из `CountPieces`, затем `PiecesTotal`, затем `LoadedPieces`; при отсутствии детализации — `1 pcs`.

PDF сохраняется непосредственно в папке **Interstate BOL** с именем:

```text
<TripID>_Interstate_BOL.pdf
```

Система создаёт отдельный BOL Number вида:

```text
IBOL-<год>-<последовательный номер>
```

Повторная обработка одного `TripID` должна вернуть существующий PDF, а не создать новый файл.

## 7. Как найти и открыть BOL

На текущем этапе ссылка на BOL ещё не отображается внутри Warehouse Control. Для просмотра используется отдельный Interstate BOL Web App: на главном экране он показывает все успешно сформированные документы, позволяет искать по TripID, BOL Number или Route и открывать PDF кнопкой **Open PDF**.

Если ссылка Web App ещё не предоставлена администратором, используйте реестр:

1. Откройте spreadsheet **Interstate_BOL_generator**:
   [Interstate BOL Generator](https://docs.google.com/spreadsheets/d/1PcMWZ0ksfD1tIGveAlAFIFvWl8Xd2lz60BDtBkZFVtM/edit).
2. Откройте лист `BOL_Registry`.
3. Найдите строку по точному `TripID`.
4. Убедитесь, что `Status = GENERATED`.
5. Откройте ссылку из `PDF URL`.

Также PDF можно найти непосредственно в папке Drive **Interstate BOL** по имени TripID.

### Резервная ручная генерация

Используйте её только если автоматическая обработка не завершилась.

1. В spreadsheet BOL откройте меню **Interstate BOL → Open generator** либо отдельный BOL Web App, если администратор предоставил ссылку.
2. Выберите TripID или введите его точное значение в `TripID override`.
3. Нажмите **Generate Interstate BOL**.
4. После успеха нажмите **Open PDF**.

Повторное нажатие для уже сформированного TripID возвращает существующий документ.

## 8. Статусы BOL и действия пользователя

### `BOL_AutoQueue`

| Статус | Значение | Действие |
|---|---|---|
| `PENDING` | TripID ожидает обработки | Подождать ближайший запуск worker |
| `PROCESSING` | PDF формируется | Не запускать ручную генерацию параллельно |
| `RETRY` | Была временная ошибка | Проверить `Error`, дождаться следующей попытки |
| `COMPLETED` | PDF сформирован | Открыть `PDF URL` |
| `FAILED` | Автоматические попытки закончились | Передать TripID и Error администратору; после исправления использовать ручной fallback |

### `BOL_Registry`

| Статус | Значение |
|---|---|
| `GENERATING` | Создание документа начато |
| `GENERATED` | PDF зарегистрирован и доступен |
| `FAILED` | Валидация или генерация завершилась ошибкой |

Поле `Lifecycle Status = DRAFT` означает только состояние документа. Оно не означает, что BOL уже выдан водителю или подписан.

## 9. Проверка готового BOL

Перед выдачей документа в рейс проверьте:

1. `TripID`, BOL Number и дату.
2. Направление:
   - NY → CA: shipper — Linden, NJ; receiver — Sun Valley, CA;
   - CA → NY: shipper — Sun Valley, CA; receiver — Linden, NJ.
3. Truck.
4. Все ожидаемые OrderID.
5. Название груза по каждому заказу.
6. Количество мест.
7. Вес каждого заказа и общий вес.
8. Количество страниц и обозначение `Page X of Y`.
9. Отсутствие пустой отдельной страницы, обрезанных строк и наложения текста.
10. Постоянные реквизиты без ошибочного `[NEED TO FILL]` в критичных для операции полях.

Если данные BOL неверны, не редактируйте PDF вручную. Передайте администратору TripID и описание ошибки. Текущая версия BOL считается неизменяемой для одного TripID.

## 10. Unloading — приёмка рейса

1. В Warehouse Control выберите **NY Unloading** или **CA Unloading** по складу назначения.
2. Выберите truck и откройте workflow.
3. В списке TripID выберите прибывший рейс.
4. Нажмите **Open Trip**.
5. Сверьте направление, truck и заказы.
6. Отмечайте только физически полученные pieces.
7. Зеленая кнопка означает received.

Статусы заказа:

- `Not received` — не отмечено ни одного ожидаемого места;
- `Partial` — отмечена только часть;
- `Received` — отмечены все ожидаемые места.

Состояние Unloading хранится только в открытой странице. Не закрывайте и не обновляйте страницу до завершения проверки.

## 11. Закрытие рейса на приёмке

1. Проверьте все заказы и места.
2. Нажмите **Close Trip**.
3. Если система показывает количество unreceived pieces, физически перепроверьте груз.
4. Подтвердите закрытие только после проверки.

После закрытия:

- по каждому заказу создаётся запись в `Receiving`;
- каждое неотмеченное место записывается в `Missing` со статусом `Open`;
- TripID исчезает из списка доступных рейсов для этого направления.

Закрытие рейса нельзя использовать как промежуточное сохранение. Отдельного draft/save для Unloading сейчас нет.

## 12. Типовые ошибки

| Сообщение/ситуация | Причина | Действие |
|---|---|---|
| `Please login first` | Сессия отсутствует или истекла | Выполнить Login повторно |
| Workflow не отображается | Нет соответствующего кода в `Users.Access` | Обратиться к администратору |
| `No newly loaded pieces to generate trip` | Нет новых отметок после предыдущих TripReports | Проверить loaded items и Save |
| `Save failed` | Нет соединения или ошибка Apps Script | Не очищать браузер, восстановить связь, Retry Save |
| Generate Trip timeout | Ответ не вернулся вовремя | Сначала проверить `TripReports`; не создавать рейс повторно вслепую |
| TripID отсутствует в BOL | Уведомление ещё не обработано либо пропущено | Проверить `BOL_AutoQueue`, подождать reconciliation или применить ручной fallback |
| BOL `FAILED` | Неполные данные, конфликт route/truck или ошибка прав | Открыть поле `Error`, исправить источник/config, повторить вручную |
| `Weight must be greater than zero` | У заказа нет корректного веса | Исправить Weight в источнике; не подставлять приблизительное значение |
| Trip не отображается в Unloading | Неверное направление либо рейс уже закрыт | Проверить TripReports и Receiving |

## 13. Инструкция администратора

### Warehouse Control

1. Управляйте пользователями на листе `Users`.
2. Для каждого пользователя задайте `Username`, `Password`, `Access`, `Active`.
3. Допустимые access codes:
   - `NY_LOADING`;
   - `CA_LOADING`;
   - `NY_UNLOADING`;
   - `CA_UNLOADING`.
4. Не изменяйте заголовки рабочих листов без проверки контракта Apps Script.
5. Не удаляйте и не редактируйте строки `TripReports` после создания BOL без отдельного процесса корректировки.

### Interstate BOL

1. Проверьте `BOL_Config`, особенно значения с `[NEED TO FILL]`.
2. `AUTO_GENERATION_ENABLED` должно быть `TRUE`.
3. У проекта должны быть разрешения на source spreadsheet, BOL workbook, Drive folder и Google Docs.
4. Должны существовать два installable trigger:
   - `processPendingInterstateBols` — каждую минуту;
   - `reconcileAutomaticBolJobs` — каждый час.
5. Контролируйте `BOL_AutoQueue` и `BOL_Registry`.
6. Не удаляйте registry row только для повторной генерации: это может нарушить связь BOL Number и PDF.
7. При обновлении BOL library создавайте новую numbered version и явно обновляйте закреплённую версию в Warehouse Control.

### Ежедневный операционный контроль

- Нет `PENDING`/`PROCESSING` старше 15 минут.
- Нет необработанных `FAILED`.
- Для каждого созданного рейса есть один `GENERATED` BOL.
- `PDF URL` открывается у ответственного пользователя.
- В папке нет нескольких PDF с одинаковым TripID.

## 14. Что передавать администратору при ошибке

Отправьте:

- точный `TripID`;
- выбранный workflow и truck;
- время ошибки по New York time;
- текст сообщения или значение `Error`;
- скриншот экрана;
- был ли создан ряд в `TripReports`;
- текущий статус в `BOL_AutoQueue` и `BOL_Registry`;
- открывается ли `PDF URL`.

Не передавайте пароль пользователя и не изменяйте рабочие строки вручную для обхода ошибки.
